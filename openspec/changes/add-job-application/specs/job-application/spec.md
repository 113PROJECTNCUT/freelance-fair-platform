# Spec Delta

## Purpose

讓會員應徵招募中的案件、發案方查看應徵並選定接案者，以及發案方主動邀請接案者應徵，建立「這個案件由誰承接」的關係，作為後續合約與里程碑的起點。

## ADDED Requirements

### Requirement: 應徵案件
系統 SHALL 允許已登入會員對狀態為 `OPEN` 的案件送出應徵，內容包含自我推薦、報價與預計天數；成功回傳 201 與應徵資料，狀態為 `PENDING`。會員 MUST NOT 應徵自己刊登的案件，同一會員對同一案件 MUST NOT 重複應徵。

#### Scenario: 應徵成功
- **WHEN** 已登入會員對別人刊登的招募中案件送出合格的應徵
- **THEN** 回傳 201，包含應徵 id、案件 id、報價、預計天數，狀態為 PENDING

#### Scenario: 未登入不能應徵
- **WHEN** 未登入者送出應徵
- **THEN** 回傳 401

#### Scenario: 不能應徵自己的案件
- **WHEN** 發案方對自己刊登的案件送出應徵
- **THEN** 回傳 403

#### Scenario: 重複應徵
- **WHEN** 會員對已應徵過的案件再次送出應徵
- **THEN** 回傳 409

#### Scenario: 案件已不在招募
- **WHEN** 會員對狀態為 IN_PROGRESS 的案件送出應徵
- **THEN** 回傳 409

#### Scenario: 案件不存在
- **WHEN** 會員對不存在的案件 id 送出應徵
- **THEN** 回傳 404

### Requirement: 應徵內容驗證
系統 MUST 驗證：自我推薦 10–1000 字、報價 1–10,000,000 元、預計天數 1–365 天；不符合時回傳 400 並指出欄位。

#### Scenario: 報價為 0
- **WHEN** 會員送出報價 0 的應徵
- **THEN** 回傳 400，錯誤欄位為 quotedPrice

#### Scenario: 自我推薦太短
- **WHEN** 會員送出少於 10 字的自我推薦
- **THEN** 回傳 400，錯誤欄位為 message

### Requirement: 發案方查看應徵
系統 SHALL 讓發案方列出自己案件的所有應徵，依應徵時間舊到新排序，每筆包含應徵者 id 與顯示名稱、自我推薦、報價、預計天數、狀態與應徵時間；回應 MUST NOT 包含應徵者 Email。非該案發案方 MUST 收到 403。

#### Scenario: 發案方查看應徵列表
- **WHEN** 發案方查詢自己案件的應徵
- **THEN** 回傳 200 與該案件的所有應徵，不含應徵者 Email

#### Scenario: 非發案方不能查看
- **WHEN** 其他會員查詢這個案件的應徵
- **THEN** 回傳 403

### Requirement: 選定接案者
系統 SHALL 讓發案方從自己招募中案件的待審應徵中選定一位：該應徵改為 `ACCEPTED`，同案件其他待審應徵改為 `REJECTED`，案件狀態改為 `IN_PROGRESS`，之後不再出現在公開案件列表。

#### Scenario: 選定成功
- **WHEN** 發案方選定某一筆待審應徵
- **THEN** 該應徵為 ACCEPTED、其他應徵為 REJECTED，案件狀態為 IN_PROGRESS 且不在公開列表中

#### Scenario: 非發案方不能選定
- **WHEN** 其他會員嘗試選定這個案件的應徵
- **THEN** 回傳 403

#### Scenario: 已選定過不能再選
- **WHEN** 發案方對已經是 IN_PROGRESS 的案件再選定另一筆應徵
- **THEN** 回傳 409

#### Scenario: 應徵不屬於這個案件
- **WHEN** 發案方以別的案件的應徵 id 進行選定
- **THEN** 回傳 404

### Requirement: 我的應徵
系統 SHALL 讓會員列出自己送出的所有應徵，依應徵時間新到舊排序，每筆包含案件 id、案件標題、案件狀態與應徵狀態。

#### Scenario: 查看我的應徵與結果
- **WHEN** 被選定的接案者查詢自己的應徵
- **THEN** 該筆應徵狀態為 ACCEPTED，案件狀態為 IN_PROGRESS

### Requirement: 邀請接案者應徵
系統 SHALL 讓發案方邀請一位開放接案的會員應徵自己招募中的案件，可附 200 字以內的訊息；成功回傳 201。不能邀請自己、未開放接案者（400），不能對同一人重複邀請或邀請已應徵者（409），非發案方 403，案件非招募中 409，會員不存在 404。

#### Scenario: 邀請成功
- **WHEN** 發案方以自己招募中的案件邀請一位開放接案的會員
- **THEN** 回傳 201，包含案件 id 與受邀者 id

#### Scenario: 重複邀請
- **WHEN** 發案方對同一位會員再次邀請同一案件
- **THEN** 回傳 409

#### Scenario: 不能邀請未開放接案的會員
- **WHEN** 發案方邀請未開放接案的會員
- **THEN** 回傳 400，錯誤欄位為 freelancerId

#### Scenario: 非發案方不能邀請
- **WHEN** 其他會員以不是自己的案件送出邀請
- **THEN** 回傳 403

### Requirement: 收到的邀請
系統 SHALL 讓會員列出自己收到的邀請，依邀請時間新到舊排序，每筆包含案件 id、案件標題、案件狀態、發案方顯示名稱、訊息，以及自己是否已應徵。

#### Scenario: 受邀者應徵後
- **WHEN** 受邀者應徵了邀請中的案件後查詢收到的邀請
- **THEN** 該筆邀請標示為已應徵

### Requirement: 案件應徵人數
案件詳情 SHALL 包含目前的應徵人數，任何人皆可查看。

#### Scenario: 應徵後人數增加
- **WHEN** 一位會員應徵後，訪客查看案件詳情
- **THEN** 應徵人數為 1
