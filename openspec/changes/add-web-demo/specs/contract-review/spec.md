# Spec Delta

## Purpose

讓接案者與發案方在簽約前，針對同一份合約看到各自的風險，並取得對等的修改建議。

## ADDED Requirements

### Requirement: 雙向風險標示
系統 SHALL 對每個條款判斷是否對接案者不利、對發案方不利或對雙方皆不利，並為每個風險項目提供風險等級（高風險／中風險）、白話說明與建議修改方向。

#### Scenario: 對接案者不利的條款
- **WHEN** 條款內容為「乙方應配合無限次修改」
- **THEN** 回傳風險項目「無限修改」，對象為接案者，等級為高風險

#### Scenario: 對發案方不利的條款
- **WHEN** 條款內容為「交付後乙方不負任何責任」
- **THEN** 回傳風險項目「接案者不負瑕疵責任」，對象為發案方，等級為高風險

#### Scenario: 否定句不誤報
- **WHEN** 條款內容為「甲方不得要求無限次修改」
- **THEN** 該條款不回傳任何風險項目

### Requirement: 合約缺漏檢查
系統 SHALL 檢查整份合約是否缺少交付期限、驗收方式與遲延責任，缺少時以合約層級的風險項目回報。

#### Scenario: 缺少遲延責任
- **WHEN** 合約全文沒有任何逾期或遲延責任的約定
- **THEN** 回傳「未約定遲延責任」，對象為發案方

### Requirement: 雙方風險分數
系統 SHALL 分別計算接案者與發案方的 0–100 風險分數，60 以上為高風險、30–59 為中風險、30 以下為安全。

#### Scenario: 條款齊全的合約
- **WHEN** 合約約定了交付期限、修改上限、驗收期限、遲延責任上限與付款期限
- **THEN** 接案者與發案方皆為安全

### Requirement: 輸入限制與免責提示
系統 MUST 拒絕空白或超過 20,000 字的內容，且每次結果 SHALL 顯示「僅供參考，不構成法律意見」。

#### Scenario: 空白內容
- **WHEN** 使用者未輸入內容就按下健檢
- **THEN** 顯示錯誤訊息，不執行審查
