# Spec Delta

## Purpose

讓發案方把案件需求、預算與驗收條件公開刊登，讓訪客與接案者可以瀏覽與查詢。

## ADDED Requirements

### Requirement: 刊登案件
系統 SHALL 允許已登入的發案方刊登案件，內容包含標題、類別、需求描述、預算下限與上限、截止日、修改次數上限、權利歸屬與驗收標準；成功回傳 201 與案件資料，狀態為 `OPEN`。

#### Scenario: 發案方刊登成功
- **WHEN** 已登入的發案方送出完整且合格的案件
- **THEN** 回傳 201，包含案件 id、狀態 OPEN、發案方名稱與驗收標準

#### Scenario: 接案者不能刊登
- **WHEN** 已登入的接案者送出刊登
- **THEN** 回傳 403

#### Scenario: 未登入不能刊登
- **WHEN** 未登入者送出刊登
- **THEN** 回傳 401

### Requirement: 刊登內容驗證
系統 MUST 驗證：標題 5–60 字、描述 20–3000 字、預算下限至少 1 且不大於上限、截止日在今天之後、修改次數 0–10、驗收標準 1–20 項且每項 1–200 字；不符合時回傳 400 並指出欄位。

#### Scenario: 預算上下限顛倒
- **WHEN** 發案方送出預算下限 50000、上限 10000
- **THEN** 回傳 400，錯誤欄位為 budgetMax

#### Scenario: 沒有驗收標準
- **WHEN** 發案方送出空的驗收標準
- **THEN** 回傳 400，錯誤欄位為 acceptanceCriteria

### Requirement: 瀏覽與查詢案件
系統 SHALL 讓任何人（含未登入訪客）列出狀態為 OPEN 的案件，依刊登時間新到舊排序，並可依類別、關鍵字（比對標題與描述）、預算範圍篩選。

#### Scenario: 訪客瀏覽
- **WHEN** 未登入訪客查詢案件列表
- **THEN** 回傳 200 與公開案件

#### Scenario: 依類別篩選
- **WHEN** 訪客以類別 DESIGN 查詢
- **THEN** 結果只包含 DESIGN 類案件

#### Scenario: 依關鍵字與預算篩選
- **WHEN** 訪客以關鍵字「形象網站」與最高預算 30000 查詢
- **THEN** 結果只包含標題或描述含「形象網站」且預算下限不超過 30000 的案件

### Requirement: 案件詳情與我的案件
系統 SHALL 讓任何人以 id 查看案件詳情（不存在回 404），並讓發案方列出自己刊登的所有案件。

#### Scenario: 查看不存在的案件
- **WHEN** 訪客查看不存在的案件 id
- **THEN** 回傳 404

#### Scenario: 我的案件
- **WHEN** 發案方查詢自己的案件
- **THEN** 只回傳該發案方刊登的案件
